# Постоянная работа с публикациями

## Поток: от ссылки к исследовательской идее

1. **Проверить наличие.** Нормализовать arXiv/DOI, искать title/ID и aliases.
   Отдельная версия препринта не становится отдельной работой автоматически.
2. **Создать inbox.** Сохранить проверенные библиографические сведения, URL,
   приоритет и темы. Не называть это разбором до чтения.
3. **Триаж.** Вопрос статьи, тип вклада, отношение к интересующей задаче,
   стоит ли читать глубже. reading_scope=abstract/partial, status=triaged.
4. **Разобрать.** Метод, предпосылки, эксперименты и сравнения, ограничения,
   альтернативные объяснения, недостающие проверки. Сохранять локаторы источника.
5. **Сопоставить с картотекой.** Найти по теме, методу, датасету и ключевым словам.
   Отделить cited prior work от фактически проверенных результатов. Связь
   «противоречит» проверять по постановке, данным, метрике и бюджету.
6. **Обновить направление.** Дополнить topic/synthesis: что подтверждено,
   на каких условиях, где расхождения и что пока не проверено.
7. **Оформить идею.** Для перспективного пробела создать idea с ожидаемым
   результатом, критерием опровержения, минимальным экспериментом и стоимостью.
8. **Проверить и проиндексировать.** validate → index → check. Просмотреть
   изменения Git, чтобы случайно не потерять прежние выводы.

## При 10–100 статьях в день

Не смешивать число принятых ссылок с числом глубоких разборов. За год это
3 650–36 500 работ; разумно различать inbox, triaged и reviewed, сохраняя scope.
Быстрый триаж может занимать одну карточку с несколькими предложениями;
полный разбор делается там, где он влияет на исследовательский вопрос.

Рекомендуемый порядок работы (не включённое расписание):

- В начале сессии — поиск новых работ относительно текущих тем и идей.
- После пачки — валидация и одна индексация всей пачки.
- При появлении взаимосвязанных результатов — synthesis с таблицей условий.
- Периодически — пересмотр revisit, дубликатов, терминов и неподтверждённых идей.

Новая тема должна отвечать на вопрос, а не просто накапливать список ссылок.
Например: «Когда дешёвый предиктор сохраняет качество при смене домена?»
В ней полезны таблица свидетельств, конкурирующие объяснения и очередь проверок.

## Правила численных результатов

Для каждого существенного результата фиксировать:

| Что | Пример |
| --- | --- |
| Модель и размер | DeepSeek-R1-Distill-Qwen-1.5B |
| Обучение и тест | обучение MATH, оценка AIME24 |
| Метрика и единица | pass@1, %; способ усреднения |
| Baseline | Uniform либо Dynamic Sampling |
| Бюджет | число rollout, токены, время, железо — что реально измерено |
| Результат | абсолютные значения; относительный прирост отдельно |
| Неопределённость | число запусков, CI/std либо «не проверено» |
| Источник | версия, Table/Figure/Section, URL |

Меньше rollout не тождественно такому же сокращению времени. Улучшение на одной
модели не переносится автоматически на другие масштабы и предметные области.
source_checked — прочитано в источнике; reproduced — реально воспроизведено.

## Как продолжить в следующей сессии

Можно сказать: «Разбери эту статью и сохрани в `/Users/roman/dev/repos/science`,
сравни с уже имеющимися работами и обнови карту направления».
AGENTS.md задаёт единый процесс для будущего ассистента в этом каталоге.
Сначала читать текущее состояние файлов: чат не является единственной памятью.
