# Формат записи v1

Каждая запись — каталог с `record.json` (UTF-8, schema_version=1) и `review.md`.
Единица хранения — работа/тема/идея/синтез, а не отдельная сессия чата.
Продолжение обсуждения обновляет существующую запись; история сохраняется в Git.

## Основные поля

| Поле | Назначение |
| --- | --- |
| id | Стабильный канонический идентификатор; обязателен и уникален |
| kind | paper, topic, idea, synthesis, question, experiment |
| title | Оригинальное название статьи или название заметки |
| year | Год работы/первого препринта, не год чтения; у собственных заметок год создания |
| status | inbox → triaged → reviewed; revisit для пересмотра; archived для неактуального |
| priority | 1 — высокая, 2 — обычная, 3 — низкая |
| reading_scope | unread, abstract, partial, full; not_applicable для собственных заметок |
| paper_type | perspective, empirical, theoretical, survey, unknown или уточнённый тип |
| source | Главный URL источника; у собственной идеи может быть пустым |
| source_version | Версия, например v1 или v2; пусто, если неизвестна |
| accessed | Дата последней фактической проверки источника, YYYY-MM-DD; пусто для unread |
| created, updated | Даты создания и изменения записи |
| summary | Короткое резюме для картотеки |
| authors | Имена авторов в оригинале; неизвестные не додумывать |
| topics, methods, datasets | ID понятий из vocab.json |
| aliases | Другие канонические ID этой же работы, например DOI |
| claims | Утверждения с уровнем доказательности и проверкой |
| relations | Направленные связи с другими записями или внешними ID |
| extra | Дополнительные структурированные поля без изменения схемы |

Все перечисленные поля присутствуют в record.json, даже если значение пустое.
Неизвестные поля верхнего уровня запрещены для обнаружения опечаток.
`validate` проверяет структуру, ссылки, уникальность ID и словарь. Он не проверяет
научную истинность, доступность URL, подлинность авторства или полноту разбора.
Он также не доказывает, что DOI и arXiv в aliases действительно относятся к одной работе.

`reviewed` означает завершённый разбор **в пределах reading_scope**.
Полноту чтения нельзя выводить из одного status. Для paper scope=not_applicable запрещён.

## Утверждение

```json
{
  "id": "c1",
  "text": "Утверждение с указанными условиями применимости",
  "epistemic_status": "reported_result",
  "verification": "source_checked",
  "source": "https://arxiv.org/html/…v2",
  "locator": "Table 1, модель X, baseline Y"
}
```

Допустимы ровно шесть показанных полей. Типы epistemic_status:

- reported_result — экспериментальный результат, **сообщённый авторами**;
- theoretical_result — формальный результат с предпосылками;
- hypothesis — гипотеза, а не установленный результат;
- interpretation — наша интерпретация;
- open_question — незакрытый вопрос.

verification: not_checked / source_checked / reproduced. Последнее только после
фактического запуска воспроизведения, с командой, окружением и артефактами в review.md.
reported_result и theoretical_result всегда требуют source и locator.
Любой source_checked/reproduced также требует source и locator.
Для своих идей допустимо not_checked с пустым внешним source.

## Связь

```json
{
  "type": "cites",
  "target": "arxiv:2507.04632",
  "status": "verified",
  "source": "https://arxiv.org/html/2610.39497v1",
  "locator": "Section 5.1; References, Qu et al. (2026a)",
  "note": "Обзор ссылается на метод MoPPS"
}
```

Типы: cites, supports, contradicts, extends, uses, related, motivates, tests.
Направление: **текущая запись → target**. Например, идея `uses` статью;
экспериментальная работа `tests` гипотезу. Не записывать обратную связь вручную:
`related` и граф умеют находить входящие связи.

Статусы: verified (наличие связи сверено с source/locator), inferred
(аналитическая связь), hypothesis (связь ещё предстоит проверить).
У verified обязательны source и locator. Любая связь требует note.
Разные источники/условия одной связи разрешены и сохраняются отдельно.

Внешние цели допустимы без карточки. Но карточку стоит создать как inbox,
если нужна очередь чтения, название и приоритет, а не только ребро графа.
Отсутствующая карточка для topic/idea/synthesis — обычно опечатка: проверь ID вручную.

## Словарь

vocab.json содержит независимые словари topics, methods и datasets.
Каждое значение — список непустых названий и синонимов, например:

```json
{"conditional-computation": ["Conditional computation", "условные вычисления"]}
```

Не создавай параллельные темы `conditional-computation` и `условные-вычисления`.
Изменение словаря требует `index`. Смена ID темы требует обновить её записи.
Численные результаты, limitations и область проверки детализируются в review.md;
машиночитаемые измерения при необходимости можно добавить в extra.experiments.

## Исследовательское расширение

`extra.research` хранит стадии, точные связи утверждений, измерения, журнал новизны и зависимости. Формат и команды: [research.md](research.md). Основной формат v1 остаётся совместимым.
